# 阶段 0 验证状态

记录日期：2026-10-28。目标是先完成 Windows → Mac 的可测量鼠标移动链路，所有“未测”项目不得推定通过。

新增实机证据见 [Mac 验证记录](mac-validation-20261028.md)：Mac 原生 release 构建与 42 项测试通过，Wi-Fi 路径下十秒合成 DrySink 成功。随后完成首轮真实鼠标共享，用户反馈“能移动，比较流畅”。有线首轮存在握手超时差异，根因未定。主观观察不等于本地鼠标、ShareMouse 的受控对照通过。

后续 [有线复测与连接诊断](connection-validation-20261028.md) 已完成：原网络实现连续两轮十秒有线 DrySink 成功，首次异常未复现。两端核心同步到 `f93e5b8`，新增分阶段连接日志与可重复启动脚本；Windows 42 项普通测试及 5 项网络测试、Mac 40 项普通测试及 5 项网络测试通过。新版一分钟有线发送正常结束，Mac 合并处理 46,830 帧，日志完整，到期正常退出且无残留监听。发送计数为 46,831，相差 1 帧尚未定位；本轮未注入系统光标，不能替代流畅度实测。

首次实机片段只含移动。后续已加入显式实验键盘、按钮、拖动和滚轮，但尚未进行这些动作的系统注入验收；断线、接收端崩溃和权限撤销下的真实释放仍需补测。

用户离家期间继续开发键盘、屏幕排列和统一前端。新增共享有序输入队列（10 项测试）以及布局校验／穿越计算（6 项测试），Windows 当前合计 60 项普通测试通过，传输诊断的 6 项显式网络测试通过。键盘、按钮和滚轮队列尚未接入协议或系统注入；布局 CLI 可计算入口，但尚未切换真实控制权。`ui/index.html` 为离线布局草稿编辑器，不能开启共享。浏览器工具拒绝本地文件预览，未进行渲染及交互视觉验收；现场输入、ShareMouse 对照及长时间真实工作负载测试等待用户回家。新增模块已通过 Apple 目标类型检查，尚未在 Mac 原生重建。

前端 JavaScript 语法检查与 24 项内存 DOM/model 断言通过（本地检查脚本 `runs/ui-check.cjs`），覆盖非法导入保留旧数据、空草稿禁用导出、恢复本地草稿、Unicode 标识及小数边缘吸附；初始示例布局另经 Rust `layout-check` 验证通过。这些检查不含真实浏览器排版、指针拖动、文件下载或视觉检查。

## 现有证据

- 五轮连接停顿补充验证：真实有序发送器与加密接收器经本机 TCP 字节中继，每轮停止双向读写/accept 约 2 秒，使用同一队列和配对身份重复 5 次。6 次认证连接、50 条逐项核对的 fake 事件；5 次停顿中的滚轮探针均已进入发送端加密排队，接收端没有收到这些探针、旧移动或新键。每轮恢复前已有旧键/按钮释放；恢复后保持暂停，物理仍按住的重复 Down/Up 被忽略，显式重新启用后的新动作成功。两端日志完整、零丢失，各 5 条预期失联错误。证据 `runs/network-stall-25268-1793167744502379400/result.json`，核心基于 `cecc4e2`，测试时工作区有未提交测试文件。fake 清理观察约 247.6–251.0 ms；解除门控后约 31.6–35.2 ms 观察到认证恢复（TCP 连接可能已在停顿期间排队），不能外推到实际网络恢复时间。使用进程内记录适配器，没有调用独立输入 worker 或系统输入。第一轮曾因中继将循环次数误记成暂停轮数而失败，修复仅在测试工具；失败原始日志保留。此证据补充 T05，**不满足 T14 在可靠传输层之前注入丢包/抖动的要求**。

- 输入进程分段计时：私有 IPC 升级 v2/80 字节，跨设备协议仍为 v2/72 字节。成功动作的 ACK 分别记录派发、worker 适配器调用和返回耗时，并验证总和、时序与当前请求身份；控制、失败和重复消费不能泄漏前次动作时间。摘要按时钟和移动/其他动作分组，同时列出缺失、无效及首个 RPC 故障。5 项 Windows fake 进程测试现额外核对实际时间记录、一次性消费及 ACK 故障只记录一次；人工延迟 fake 另验证时间戳包围适配器调用。Windows 时钟低粒度不作为 Mac 延迟证据，成功样本受 30 ms 截断，不代表无卡顿；Mac 原生计时和可见对照未测。

- 独立输入进程：实验 `--inject-actions` 路径加入继承管道、活动租约和 worker 自有输入记录；默认仅移动路径不变。Windows 5 项真实隔离进程测试通过，涵盖父进程强杀、父循环停止推进、正常清理并确认 ACK/进程退出、半帧 EOF、ACK 故障；worker 的进程身份及实际退出由只读系统句柄核验。另有 7 项协议/租约测试和 3 项 fake adapter 故障测试，通过响应写阻塞、Down 后 panic、部分释放失败。新维护回调暴露一次正常停止被误标为适配器错误的竞态，保留停止分类后，加密动作/重连/终端停止回归通过。一次早期假输入建立前的 30 ms Reset ACK 超时导致安全拒绝，没有产生 Down；保留在 `runs/injection-worker-ack-failure-39976-1793165721832926600`，未放宽期限或静默重试。最新完整 5 项进程测试通过。Mac 只有 Apple 目标类型检查，尚未原生重建或进行真实输入；worker 被杀、整个进程树被杀、系统崩溃与 native 调用永久阻塞不在恢复保证内。实验路径 t3→t4 包含 IPC 及 ACK，不能与旧版纯本地注入调用时间混为一谈。

- 原生界面与共享内核：新增 Rust C ABI（桥接源 `992c56f`）和 WinUI 3 布局客户端。桥接不采集输入、不创建连接，只执行能力查询、布局校验和穿越预览。独立 C 消费者真实链接 DLL 通过。布局精度修复 `67d5522` 启用精确 JSON 浮点往返，回归覆盖一 ULP 的缝隙、重叠及跨边缘终点；Windows 核心 82 项普通测试、桥接 7 项测试、workspace Clippy/fmt 和 Apple 全目标类型检查通过。WinUI 编译 0 错误/0 警告，C# → Rust 七项无窗口自检通过；当前目录构建 170.54 MiB，含运行库。未做原生窗口视觉、拖动、文件对话框或闲置资源测试：Computer Use 应用访问授权等待超时。Mac SwiftUI 构建在独立聊天进行，最新桥同步/接入仍待工具授权，源码尚未汇入主分支。
