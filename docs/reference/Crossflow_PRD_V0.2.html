Crossflow 产品需求文档

跨设备双向键鼠共享系统 | 需求基线 V0.2

01 项目目标与范围

Crossflow 为多台保留独立桌面与应用的设备提供双向键鼠共享。设备之间不传输屏幕画面，用户通过移动鼠标跨越屏幕边界切换控制目标，键盘焦点随之切换，并可同步剪贴板。首个产品目标是替代 Windows 与 Mac 之间的 ShareMouse 日常使用。

产品优先验证 Windows 鼠标控制 Mac 时的可见流畅度。只有在目标实机上证明原型改善了现有体验，并能安全恢复控制，才进入完整桌面 MVP。界面美观和功能数量不能替代这项验证。

文档基线

版本 V0.2，日期 2026年10月27日。V0.1 中明确的产品目标与设备范围予以保留。本版补充需求编号、验收口径、发布边界及阶段 0 依赖；新增的定量门槛、控制权策略和坐标策略均标为建议，需通过阶段 0 冻结。本文不代表已经完成实机验证。

首版范围边界

阶段 1 的最低验收拓扑为一台 Windows 和一台 Mac，支持多显示器及错位布局。底层保留多节点扩展能力；三台及以上同时接入的发布承诺，在阶段 0 后单独确认。macOS 最低版本、芯片架构及显示器组合以兼容性矩阵冻结为准。

MVP 面向已登录的普通桌面会话和键盘鼠标输入。触控板多指手势、手柄、跨公网控制、远程画面、远端登录与安全桌面控制不在首版承诺内。图片、富文本、文件跨设备拖放列为 P1。

02 核心功能需求

P0 表示桌面 MVP 发布必需，P1 表示核心体验扩展，研究项表示尚未承诺可交付。阶段 0 只验证 P0 的关键技术与风险，不要求完成全部产品界面。

编号需求MVP 验收口径
CF-01P0 双向与对等控制Windows 和 Mac 均可作为输入源或目标；用户无需切换 Server 或 Client 身份。
CF-02P0 自由屏幕布局以屏幕为布局单位、设备为连接单位；可拖动上下左右关系、错位与部分边缘重叠，并保存布局。
CF-03P0 跨屏与连续性仅从相邻可通行边缘穿越；双向进入位置按既定映射计算，不误入非相邻屏，不发生非预期跳跃。
CF-04P0 键盘与鼠标焦点键盘跟随当前目标；移动、点击、双击、滚轮、按住拖动、按键按下与抬起均正确处理。
CF-05P0 流畅度通过阶段 0 的可见效果与日志双重验收；以本地鼠标和 ShareMouse 为对照，不以发送频率代替体验。
CF-06P0 恢复连接短时断网、网络恢复、休眠唤醒后自动重连，不重新配对；重连不回放过期输入、不主动夺取焦点。
CF-07P0 游戏保护提供本地可用的快捷键锁定与解除；锁定时停止跨屏并显示状态。自动游戏识别为 P1。
CF-08P0 文本剪贴板已授权设备双向同步 Unicode 纯文本，覆盖中英文、多行与空内容；支持关闭，避免循环同步和旧值覆盖。
CF-09P0 桌面界面Windows 托盘与 macOS 菜单栏常驻；可查看连接、权限、当前目标、锁定状态，完成配对、撤销与布局配置。
CF-10P0 本地运行核心功能不依赖账号、激活服务器或公网；断开互联网但保留局域网时，配对与共享仍可使用。
CF-11P0 安全与恢复显式配对、身份校验、链路加密、权限控制、输入循环防护、断线释放及紧急恢复同时具备。
CF-12P0 控制权一致性每个目标同一时刻只接收一个已授权远端控制源；本地恢复优先，冲突时不交错注入多个来源的按键。

后续体验完善

P1 包括图片与富文本剪贴板、文件跨设备拖放、布局预设、自动吸附、屏幕热插拔恢复、可定制 Ctrl/Cmd 与 Alt/Option 映射、边缘阻尼、快捷键切换目标、用户可见延迟诊断、多网卡绑定、自动发现和线路故障切换。阶段 0 所需诊断日志先于完整诊断界面实现。

03 交互规则与异常处理

屏幕布局与边缘穿越

屏幕拥有稳定标识、所属设备、尺寸、方向、缩放及布局坐标。相邻关系由边缘接触的有效区间决定，部分重叠仅开放重叠区间；没有邻屏的边缘停留在本屏。布局必须避免屏幕互相覆盖造成目标歧义。

阶段 0 建议采用逻辑坐标和有效边缘区间比例映射，显式转换到各系统注入坐标。物理尺寸映射保留为替代方案。跨屏后保留剩余位移并防止同一事件反复穿越；具体映射公式、角点规则和阈值由试验冻结。

同一设备内部的多屏移动优先保持系统行为。拖动中允许传递鼠标按住状态，但不得把“窗口拖到另一台电脑”或“拖动文件即可传输”混同为 P0；跨设备文件传输属于 P1。屏幕消失时先停止向无效目标注入，释放远端状态并恢复本地控制，完善自动重排属于 P1。

控制权策略建议

  • 每次控制会话记录来源、目标、会话编号与有效期；网络连接的发起方不等于固定输入主机。
  • 本地紧急恢复始终最高优先级。目标设备出现有效物理操作时，建议撤销远端会话并恢复本地；轻微鼠标抖动的判定阈值需试验。
  • 并发抢占由目标端按固定规则裁决；失去控制的一方收到明确状态，不通过“最后到包者获胜”来交错注入。
  • 切换时释放旧目标由本会话注入的按键和鼠标按钮；初版建议要求仍被物理按住的修饰键重新按下后生效，避免意外快捷键。
  • 注入事件携带可识别来源，接收端不得再次把它作为物理输入转发；捕获与抑制能力需逐平台验证。

故障处理要求

触发条件期望行为
断网或会话超时终止远端控制，释放该会话持有状态，恢复本地；过期输入不得在恢复后重放。
接收进程崩溃验证清理机制是否仍可执行；若需要独立监护进程，则在进入日常使用前补齐。
权限撤销或注入失败停止失败会话，显示可理解的权限提示，不显示虚假的“正在控制”。
设备被撤销信任拒绝新旧连接和继续输入；重新使用必须重新确认配对。
快捷键冲突或按键卡住通过不可远端触发的本地紧急恢复路径停止共享，清理本会话状态。

Windows SendInput 受进程完整性级别限制，不能把普通权限注入成功外推到提权窗口或安全桌面。应将这些情形列入兼容性测试并明确提示。[S1]

04 性能与隐私要求

性能必须分层衡量

维度要求与证据
输入采集覆盖设备实际支持的轮询率；记录接收间隔分布、突发和遗漏，不能把标称轮询率视为实际采样结果。
队列与传输移动数据允许有界合并，不能无限排队；相对位移合并要保留位移总量。按键和按钮状态不能简单丢弃。
目标注入分别测量接收排队与注入调用耗时；调用成功只说明提交，不能证明光标已经显示。
可见运动在同一目标显示器对照本地、ShareMouse 与原型，评估停顿、速度连续性、拖尾与跨屏跳变。
长期稳定持续使用后无积压、卡键、输入循环或失控；CPU、内存及事件量作为诊断和功耗基线。

各项延迟报告至少包含中位数、P95、P99、最大值和样本量。两台机器的单调时钟不能直接相减；没有时钟同步误差界限时，只报告各机内部耗时、往返时间和可见端到端观测。不得用往返时间的一半冒充精确单程延迟。

具体性能数值由阶段 0 提出并验证，首次采样前固定判定口径。建议以目标显示器刷新周期为基准评价可见停顿与附加延迟，同时保留毫秒值；不同刷新率、网络和硬件组合分别出结论。

网络与权限

支持 Wi-Fi、局域网以太网及独立以太网直连。MVP 至少支持手动选择或指定可达地址；自动发现不能自动授予输入权限。发现服务不可用时仍应有直接连接路径。设备身份与 IP 地址分离，以便网络变化后恢复已授权连接。

控制与剪贴板通道使用经过维护的认证加密机制，不自创密码算法。首次配对需由用户核验两端身份，提供设备级授权与撤销。错误身份、未配对设备、重放事件及旧会话数据不得被注入。具体协议与密钥存储方案在阶段 0 后冻结。

日志与剪贴板

性能日志默认只记录时间戳、序号、类型、队列深度和状态结果，不记录用户键入的文字或剪贴板正文；功能测试使用专门的虚构文本。诊断导出由用户主动触发。剪贴板需要同步开关、内容版本和回环抑制，重连不得把旧缓存覆盖为新的本地内容。并发复制的裁决规则在 MVP 前明确。

05 架构与交付路线

架构候选

建议采用 Rust 共享核心，承载协议、连接、布局、控制权、安全与诊断；输入捕获和注入由平台适配层完成。每台设备运行对等节点，同一时刻的输入方向由控制会话决定。共享核心与界面框架分离。

层次候选与待验证事项
WindowsRaw Input 与 SendInput 作为候选；输入抑制、注入识别、权限边界需补充平台机制并验证，不能假定 Raw Input 本身负责拦截。
macOSCoreGraphics 事件捕获和注入作为首轮候选；HID 路线按权限、可分发性与流畅度结果评估。
Linuxevdev 与 uinput 为后续候选；Wayland、桌面环境和 SteamOS 游戏模式单独验证。
网络比较可靠流与具备认证加密的数据报方案；优先保证状态顺序和移动数据时效，不提前指定 TCP、UDP 或 QUIC 为最终答案。
界面SwiftUI 与 Windows 原生界面、Tauri 均为候选。原生使用体验是需求，框架由阶段 0 后的集成成本决定。

06 移动路线与待决事项

移动设备研究范围

路线 A 为 Windows → Mac → iPad 的 Universal Control 桥接。Apple 官方功能需要兼容的 Mac 与 iPad，并满足 Apple Account 等条件；官方说明没有在本次核验中确立 Crossflow 软件注入事件可被接力，因此必须实测。[S2] 该外部依赖不改变 Crossflow 桌面核心无需账号的要求。iPhone 不应由这条 iPad 验证路线推定支持。

路线 B 为 Bluetooth HID 外设模拟。优先调查 Windows 和 macOS 在具体蓝牙适配器与权限条件下的纯软件可行性；无法证明可行时，再验证 ESP32 等独立桥接硬件。蓝牙连接成功不等于完成系统级键鼠控制。

路线 C 为原生客户端，承载设备管理、剪贴板、文件及远程触控板能力。沿用 V0.1 的范围约束：不把普通 iPadOS 或 iOS App 当作任意系统级输入注入通道，相关系统控制能力需额外路线验证。三条路线可组合，但都不阻塞桌面 MVP。

本版优先级调整

安全配对、权限控制、紧急恢复与控制权仲裁由原 P1 或未决问题提前到 P0；快捷键游戏锁定从阶段 2 前移至阶段 1，自动识别仍为 P1。完整热插拔体验为 P1，但屏幕消失时的安全恢复属于 P0。
