Crossflow 阶段 0 验收计划

技术验证 测量方法 进入 MVP 的条件 | V0.2

01 验证目标与执行顺序

阶段 0 要回答三个问题：Windows → Mac 的鼠标体验是否能够明显改善；Windows 与 Mac 是否能够双向、安全地共享输入；发现的限制是否允许进入桌面 MVP。结论必须绑定具体硬件、系统、刷新率和网络条件。

本计划版本 V0.2，日期 2026年10月27日，配套 Crossflow 产品需求文档 V0.2。以下次数、时限与相对性能阈值属于建议初始门槛，尚无实测结果；测试负责人应在首次正式采样前冻结为测试基线，不得观察结果后追改门槛。

分步执行

顺序工作包产出与停止条件
S0 准备记录硬件、权限、显示器、网络和现有 ShareMouse 行为环境清单与本地基线；无 Mac 或高刷新率设备则标记对应项目未测
S1 单向鼠标Windows 采集，Mac 注入，单条已授权连接，无跨屏 UI原始日志与三方对照；先证明是否能改善核心问题
S2 双向输入加入 Mac → Windows、键盘、按钮、滚轮和来源识别输入正确性与无回环证据；存在失控或卡键则先修复
S3 控制与故障验证控制权、紧急恢复、断线释放和重连安全恢复测试记录；关键故障未解决不得进入日常使用
S4 布局原理用最小配置验证多屏、缩放、错位和边缘映射坐标策略结论与跨屏录像；无需完成布局编辑器
S5 iPad 实验Mac 本地输入与软件注入分别测试 Universal Control可行、不适用、失败或证据不足的独立结论，不阻塞桌面结果

实验原型边界

第一条跨机链路就应限制为已显式授权的设备，并具备身份校验、加密、可用的本地停止入口与会话超时。允许使用最小界面或配置文件；完整配对界面、拖动式 Arrangement、剪贴板与安装更新器留给 MVP。不得把受控实验中的简化实现当作已经达到全部 P0。

开始前确认

  • 硬件与系统：Windows 11 版本、Mac 型号与 macOS 版本、目标显示器的实际工作刷新率及连接方式。
  • 输入与网络：同一鼠标、DPI、可选轮询率、加速设置、网卡与链路路由；具备局域网或独立有线连接。
  • 测量资源：能导出结构化日志；优先准备至少 240 fps 的外部拍摄设备，并记录其时间分辨率与误差。

02 对照设计与测试矩阵

对照组

组别操作方式用途
A 本地鼠标将同一物理鼠标直接接入目标电脑，使用相同目标显示器建立目标系统自身的可见运动基线
B ShareMouse由来源电脑的鼠标控制同一目标电脑，记录软件版本与配置复现当前问题，衡量替代方案的实际改善
C Crossflow 原型同一来源、目标和网络，运行当前原型构建验证改善及回归风险
D 目标机合成轨迹在目标机按已知轨迹产生注入事件，不经过网络帮助定位注入与显示瓶颈，不能替代真实鼠标端到端验收

正式三方对照只在同一条件下比较。每个组别预热 2 分钟，按随机顺序完成至少 5 轮、每轮 60 秒的持续运动；另做点击、拖动和键盘任务。保存试验顺序与所有轮次，不能只选最平滑的一段。人工移动只能作为可重复动作的近似，需记录这一限制。

分层覆盖矩阵

维度首轮必测扩展或降级说明
方向Windows → Mac；Mac → Windows两方向分别出结论，不用单向结果覆盖双向
显示Mac 最高可用刷新率及 60 Hz 对照；Windows 实际模式若硬件不支持高刷新率，不能通过高刷新率体验目标
鼠标设备支持时测 125、500、1000 Hz只填写实际支持值，不能把驱动标称值作为实测
网络有线基线、日常 Wi-Fi；具备条件时独立以太网直连按接口和路由分开记录；直连缺失列为未覆盖
布局左右、上下、部分边缘重叠、缩放不一致有多屏硬件时增加同机两屏与负坐标、纵向显示器
负载空闲桌面与可重复的日常负载全屏游戏验证锁定；受保护应用单独标记权限限制

不要求先做完整笛卡尔积。先在有线、高刷新率、常用轮询率下比较 A/B/C；确定候选后每次只改变一个变量，补充 Wi-Fi、缩放与双向场景。可变刷新率应先固定或明确记录，不能默认配置值就是实际显示节奏。

观察任务

匀速横移、慢速画圆、快速折返、小目标指向、窗口内拖动和滚动。任务应分别考察停顿与路径连续性，不能用更长的平滑缓冲掩盖延迟。为实机录像固定背景、光标样式、相机角度和曝光设置。

03 测量定义与记录格式

软件链路时间点

记录点含义可得指标
t0 与 t1 来源端t0 为捕获回调，t1 为交给传输层t1 − t0 为来源端处理及排队，不含物理设备到回调的完整延迟
t2 与 t3 目标端t2 为目标端收到完整事件，t3 为注入调用开始t3 − t2 为接收端处理及排队
t4 目标端注入调用返回t4 − t3 为调用耗时，不是显示完成时间
RTT独立探测的往返时间诊断网络变化；不能直接当作单程延迟
可见时刻外部录像中目标光标第一次响应或后续位置改变用于可见端到端延迟或更新间隔，误差由拍摄方式限定

跨机 t2 − t1 仅在已建立时钟偏移、漂移与误差范围时报告为估计单程耗时，并同时给出误差。未同步时保留两端原始时间戳用于关联，但不计算伪精确的单程值。

可见运动测量

定义刷新周期 T = 1000 / H 毫秒，H 为测试时确认的目标刷新率。持续匀速运动片段中，统计光标可见位置更新间隔 G；G > 2T 作为候选异常停顿。录像量化误差为 E 时，仅当 G − E > 2T 才计入明确停顿，其余标为不确定。慢速小于一个像素的自然停留不能当作卡顿。

240 fps 录像单帧间隔约为 4.17 ms，测两个时刻之差还需考虑双端定位及滚动快门误差。报告观测值和误差范围；证据分辨率不足以区分方案时结论为“证据不足”。屏幕录制可作补充，但是否捕获系统光标及录制节奏需核实。

端到端响应需要同一时间基准下的物理输入标记与显示响应，例如同步入镜的动作或可验证触发装置。若没有可靠输入标记，只报告可见更新节奏和主观延迟，不声称测得精确端到端延迟。

最小日志与结果字段

每次运行记录 run_id、构建版本、方向、源与目标设备、系统、显示模式、鼠标设置、链路、加密与传输配置、轮次、开始时间。事件记录会话编号、来源、递增序号、事件类型、t0 至 t4 五个处理时间点、队列深度、合并计数、丢弃原因和注入结果。避免记录真实键入文本。

每轮输出有效时长、样本量、事件间隔及各段耗时的 P50/P95/P99/最大值、最长连续停顿、明确停顿率、积压峰值、CPU 和内存。记录缺失、失败与异常轮次，不用总体平均值掩盖失败轮次。

04 功能与故障验收用例

以下为阶段 0 核心用例。通过需提供可复现步骤、预期和实际结果、构建与环境、日志及必要录像。未运行记“未测”，不得填写“通过”。

用例步骤与覆盖建议通过条件
T01 双向输入
CF-01/04		两方向分别执行移动、100 次点击、20 次拖动、20 次滚动；100 组按下抬起，覆盖 Shift/Ctrl/Alt/Cmd无漏点击、误点击、粘住按钮或残留修饰键；键盘布局与输入法差异有记录
T02 回环抑制
CF-11		双方捕获开启，发送已标记序列后停止物理输入，观察事件数量与来源停止后不自发继续转发；注入事件不被当作新物理输入
T03 控制仲裁
CF-12		双端同时移动、输入、请求切换；目标本地操作夺回，重复 20 轮单一远端控制源生效；无双向争抢振荡，无交错按键；建议 500 ms 内本地可控
T04 紧急恢复
CF-11		远端移动中、按键按住时、失联时分别触发本地恢复，共 20 次建议 500 ms 内停止远端注入并恢复本地；旧会话不得立即再次抢占
T05 断线与重连
CF-06/11		分别按住修饰键、字母键和鼠标按钮，断网或停止来源进程，10 轮；再恢复网络建议失联后 1 s 内释放本会话状态；可达后 10 s 内重连，无重新配对、旧事件回放或自动抢焦点
T06 崩溃与休眠
CF-06/11		接收进程强制退出、两端分别休眠唤醒、权限撤销、切换网络，各 5 轮本地输入可恢复，重启后无残留；接收端崩溃后的释放失败须列阻塞缺陷，不能以重连成功代替
T07 跨屏映射
CF-02/03		各布局在有效边缘跨出与返回各 50 次；覆盖错位、角点、缩放与负坐标无误入、穿越循环或非法坐标；计算后的入口与实际位置误差建议不超过 2 个目标逻辑像素
T08 游戏锁定
CF-07		游戏或全屏测试程序内持续向边缘移动 2 分钟；重复锁定与解锁 20 次锁定时不跨屏；快捷键本地可用；退出或失去焦点不产生卡键
T09 身份与会话
CF-10/11		未配对连接、错误身份、已撤销设备、旧会话重放各 10 次；保留 LAN 断开 WAN非授权输入全部拒绝；已配对设备可离线共享；首次本地配对可完成

中文输入法与键盘布局至少做基本录入与修饰键验证；可自定义映射属于 P1。纯文本剪贴板 CF-08 与完整配置界面 CF-09 在阶段 1 完成产品验收，不以阶段 0 未实现判定输入链路失败。

05 流畅度与网络压力验收

建议性能门槛

性能门槛仅用于阶段 0 决策，需在首轮正式试验前冻结。对每个声明支持的关键配置分别判断，至少包括 Windows → Mac 高刷新率有线场景及 Mac → Windows 常用配置。

用例测量方法建议通过条件
T10 可见流畅度
CF-05		按 A/B/C 对照，逐轮计算 G 的 P95 和明确停顿率，比较 5 轮中位结果C 的 G P95 不高于 A + 1T；明确停顿率不高于 A + 1 个百分点。若 B 有可复现停顿，C 相对 B 降低至少 30%
T11 响应延迟
CF-05		具备可靠物理触发标记时测可见端到端延迟，报告 P50 与 P95 及误差有线场景建议 C 相对 A 的附加 P95 不超过 2T；C 相对 B 不出现超出测量误差的延迟恶化
T12 用户实机评价
CF-05		随机隐藏 B/C 标签，完成至少 10 组配对任务，先以 A 校准手感建议至少 8 组认为 C 更顺滑，且没有稳定出现的明显滞后或瞄准困难；仅作为个人使用验收
T13 持续运行
CF-05/11		候选方案连续运行 30 分钟，中间穿插输入与切换，记录事件量和队列趋势无崩溃、回环、卡键；队列不持续增长，停止输入后不继续追赶旧移动
T14 网络扰动
CF-06/11		分别施加 1% 丢包、20 ms 抖动和 2 s 中断，各 5 轮；可靠流方案在传输层之前模拟不永久卡键、不重复点击、不回放旧移动；恢复满足 T05。扰动期间流畅度单独报告，不要求等同有线基线

T10 的改善应在至少 4/5 轮方向一致，且差异超出测量误差。若 B 在该配置未出现停顿，不能宣称“降低 30%”；此时要求 C 不劣于 A/B，并在真实问题配置继续复现。若 T11 缺少设备、T10 误差过大或主观与客观结果冲突，标记有条件继续，补证据后再宣称接近本地。

诊断分支

  • 网络稳定但光标仍不顺：用 D 组隔离网络；比较目标端排队、注入节奏及可见更新，不直接归因于带宽。
  • 高发送频率但注入成批出现：检查接收队列、调度和合并策略；只改变一个参数后重新采样。
  • 路径变平滑但响应变慢：回查缓冲和加速策略，不能以延迟换取表面平滑后判定通过。
  • 丢失移动后位置漂移：检查相对位移累计与状态校正；合并移动事件不等于丢弃未累计的位移。

06 移动实验与阶段决策

T15 Universal Control 桥接

先在满足 Apple 官方前提的 Mac 与 iPad 上证明本地物理鼠标可以通过 Universal Control 控制 iPad；基线失败则记录环境不适用，不评价软件桥接。[S2] 接着测试 Mac 本地合成事件，再测试 Windows 经 Crossflow 到 Mac 的事件。分别记录鼠标移动、点击、滚轮、键盘和修饰键能否接力。

在 iPad 主屏幕与至少两个其他 App 中各重复 10 轮，要求输入实际影响系统或目标 App。仅在 Crossflow 自有界面出现事件日志不算通过。若系统级接力失败，保留系统版本、注入方式与复现录像，结论限于已测试条件，不推定所有软件路线均不可行。

纯软件 HID 的接口和适配器能力调查可随后开展；必要时安排独立硬件验证。iPhone 另立验证任务，不由 Universal Control 的 iPad 结果外推。移动实验无论成功与否均不阻塞桌面阶段决策。

阶段判定

结论判定依据后续动作
进入阶段 1T01 至 T09、T13、T14 关键行为通过；T10 至 T12 在目标条件下有足够证据，核心体验改善可复现冻结首版兼容矩阵与技术选择，完成剩余全部 P0
有条件继续验证核心方向有改善，但测量证据、硬件覆盖或边界能力不足列出缺口和补测条件，继续阶段 0，不宣称可日常替代
暂停扩大功能没有可复现的流畅度改善，或存在未经授权控制、回环、无法恢复的卡键等问题优先定位或更换技术路线，解决后再复验
