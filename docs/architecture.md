# Crossflow 架构说明

Crossflow 采用 Rust 共享核心和统一客户端架构。Windows、macOS 以及后续 Linux 客户端复用协议、安全、连接、控制状态和诊断代码；平台差异集中在系统输入捕获、事件注入、权限和桌面集成适配层。Python 探索实现已经弃用，不作为客户端或共享核心继续开发。

## 阶段 0 的实际边界

当前验证链路为 Windows → Mac，默认仅鼠标相对移动；显式实验模式已接入键盘、按钮、拖动及滚轮的来源捕获、共享传输和 Mac 适配。完整 Arrangement 控制权交接和剪贴板尚未实现。Windows 来源端不拦截或隐藏本地输入；默认模式下点击不转发，实验模式下本地键盘与点击仍作用于本地应用。

接收端默认只记录数据，不操作系统光标；只有显式指定 `--inject` 才调用 Mac 系统接口。Mac 注入目前限制在主显示器，`gain` 将 Windows 原始鼠标计数线性转换为 Mac 逻辑坐标，不复刻 macOS 原生鼠标加速曲线。因此必须分别评价运动节奏、指向手感和可见延迟。

阶段 0 的发送端和接收端是实验角色，不是产品固定主从关系。后续同一个节点可同时具备采集和注入能力，以控制会话确定当前来源和目标；本版不宣称已完成双向控制与多源仲裁。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `src/main.rs` | 所有平台共享命令入口，组织配对、发送、接收、采集、环境检查与汇总 |
| `src/protocol.rs` | 版本化二进制事件帧、字段边界和编码校验 |
| `src/security.rs` | 配对静态身份、对端公钥绑定、Noise 握手和认证加密 |
| `src/session.rs` | 网络连接、非阻塞收发、租约、会话恢复和平台注入接口 |
| `src/state.rs` | 显式启用、暂停、累计位移、序号与过期事件校验 |
| `src/input.rs` | 有序输入队列：按钮、滚轮和键盘是移动合并的边界；物理状态快照、控制代际与过期丢弃 |
| `src/arrangement.rs` | 经过校验的逻辑屏幕布局、相邻边缘及单次穿越计算；尚待接入控制权切换 |
| `src/metrics.rs` | 有界异步日志、采样记录和分位数汇总 |
| `src/shutdown.rs` | CLI 终端信号转为协作式停止；正常线程释放输入和结束日志 |
| `src/platform/windows.rs` | Raw Input 相对鼠标采集，以及本地启停快捷键 |
| `src/platform/macos.rs` | CoreGraphics 光标移动、权限检查、显示环境与 Escape 停止检查 |

## 输入和传输路径

```text
Windows Raw Input
  → 共享累计位移状态
  → 版本化二进制帧
  → Noise KK 认证加密和 TCP_NODELAY
  → 会话租约及序号校验
  → Mac CoreGraphics
```

捕获回调不直接进行网络写入。来源端在共享状态中累计相对位移，网络线程按配置发送；合并事件时保留累计位移，而不是丢弃每个被合并事件的移动量。应用层只允许一个待写入密文帧，发送长时间阻塞时结束会话，避免无限排队后追赶旧光标位置。TCP 自身的缓冲和队头阻塞仍需通过实测评价，不能因开启 `TCP_NODELAY` 就断言网络延迟已经解决。

当前加密套件为 `Noise_KK_25519_ChaChaPoly_BLAKE2s`。两端在握手前已持有对方的静态公钥，通过可信通道交换各自的配对包；握手不承载输入。连接建立后仍要求本地显式启用。协议和安全层使用成熟密码库，不自行设计加密算法。

## 启停与失联行为

- Windows 按 `Ctrl+Alt+Space` 切换共享状态，`Ctrl+Alt+Esc` 停止；连接尚未就绪时不能启用。
- 每次新连接均从暂停状态开始。重新启用时重新建立位移基线，不追补暂停期间的移动。
- 接收端发出短时租约，来源端回传；过期租约、重复序号、过旧的来源端待发移动和异常位移会使会话失败。
- 网络断开后可以重新连接，但真实输入不会自动恢复共享。合成诊断模式是单独标识的测试路径，不可用它替代人工启用测试。
- Mac 按 Escape 停止接收。平台权限不足时不得把无效提交显示为成功控制。

实验输入采用协议 v2，双方均需升级。默认开关不变，Windows 使用 `--experimental-inputs`，Mac 实际动作注入另需 `--inject --inject-actions`。共享接收器跟踪本会话尝试按下的键与按钮，即使适配器调用可能已产生副作用后报错，也会尝试释放；所有普通退出路径统一清理，释放失败终止接收，不重新监听。原生适配器也保留拥有状态，清理绕过针对新输入的紧急停止／显示条件检查。强制杀进程不能依赖析构清理，尚无独立监督机制，不能宣称系统卡键恢复已验收。

输入队列只在相邻移动之间合并，保留点击、滚轮和按键顺序。键盘事件以 HID Keyboard/Keypad usage 表示物理键身份，不携带文本；编码范围依据 [USB-IF HID Usage Tables 1.7](https://www.usb.org/sites/default/files/hut1_7.pdf) 第 10 节。Windows 扫描码映射与 Mac ANSI 子集映射已加入；Ctrl 保持 Control，GUI 对应 Command。可配置 Ctrl/Cmd 策略、长按重复、锁定键与国际键位仍待实现。来源时间戳与发送轮询时钟独立检查，保留捕获到获取锁之间的等待时间；不能把队列清空或原生提交返回当作系统释放成功。

布局采用统一逻辑坐标，允许负坐标及错位；屏幕内部不可重叠，只有精确相邻且有有效重叠的边缘可穿越。角点和有效区端点不选择目标，缝隙不吸附跨越。穿越结果提供全局入口、目标局部入口与剩余位移比例，实际缩放、屏幕发现及跨设备控制交接由后续适配负责。

## 统一界面方向

用户要求内核与界面分离，以轻量、美观、响应快为界面选型标准，不要求网页技术。桌面首版优先采用 macOS [SwiftUI](https://developer.apple.com/swiftui/) 与 Windows [WinUI 3](https://learn.microsoft.com/en-us/windows/apps/winui/winui3/)；两端共享设计变量、信息结构和交互规则，原生视图分别实现。Electron / Tauri 不作为默认方案；`ui/` 保留为交互草稿，尚未实现正式原生客户端，也没有资源占用或响应速度的实测结论。

Rust 核心拥有连接、权限状态、控制权、布局校验、输入与诊断数据；界面只提交配置／操作命令并订阅状态。每个高频键鼠事件都直接走核心与平台适配器，不经过 UI 线程或视图桥接。关闭配置窗口与停止共享是不同的显式操作，后续托盘／菜单栏宿主需要独立管理核心生命周期。

Windows 托盘、macOS 菜单栏、系统权限提示和安装分发由各平台适配，但保持一致的产品流程。当前命令行是阶段 0 测量入口；Windows 另提供原生实验控制窗口，直接反映共享核心的连接和启用状态，支持开始、暂停及停止按钮。这不是完整布局编辑或正式客户端界面。客户端桥接 API、打包和原生页面仍待实现。

CLI 的终端停止使用平台信号处理器和原子请求标志，工作线程主动退出并清理；`receive_with_stop` 本身不安装进程级信号处理器，未来原生客户端可接入自己的停止令牌。Unix 直接使用已有锁定版本 `libc` 的 `sigaction` 类型与常量（MIT OR Apache-2.0）；Windows 使用 `windows-sys`。不依赖在信号上下文内操作 UI、执行输入释放或写日志。

## 性能证据的边界

日志分别记录来源端处理、接收端处理和注入调用时间。两端时钟未同步，不直接相减计算单程网络延迟。系统注入调用返回也不等于光标已显示。

本地鼠标、ShareMouse 和 Crossflow 应在同一目标显示器、刷新率及网络条件下对照；实际光标顺滑度和可见端到端响应需要独立录像或实机观察。日志、合成输入和本机回环测试只能提供链路证据，不能替代 Mac 实机可见效果验收。
